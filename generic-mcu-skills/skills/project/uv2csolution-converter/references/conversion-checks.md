# Conversion checks

## Core mapping

| µVision input | Csolution output/check |
|---|---|
| `.uvmpw` project entries | One `solution.projects[]` entry per project; paths relative to the solution |
| `TargetName` | `target-types[].type`; normalize unsupported spaces while preserving meaning |
| `Device`, `Vendor` | `target-types[].device` using `vendor::device` syntax |
| `PackID`, RTE packages | `packs[]`; preserve recorded exact versions by default and report intentional upgrades |
| `nSecure=1/0` | `processor.trustzone: secure/non-secure` |
| compiler/debug/optimization fields | `compiler`, `debug`, `optimize`, `language-*`, and compiler-scoped `misc` |
| defines and includes | `define`, `define-asm`, `add-path`; preserve target/group/file scope |
| groups/files | `groups[].files[]`; preserve exclusions and file-specific controls |
| RTE components | `components[]`; verify selection against installed pack versions |
| scatter file | `linker[].script`; confirm the referenced configuration instance exists |
| executable/library output | `output[].type`; verify output names and extensions |

## TrustZone workspace

For a secure project `Secure` and a non-secure project `App`:

```yaml
# Secure.cproject.yml
project:
  setups:
    - setup: Secure options
      processor:
        trustzone: secure
  output:
    type:
      - elf
      - cmse-lib
```

Exact `output` serialization varies by supported CMSIS-Toolbox version; let `csolution` validate it.

```yaml
# App.cproject.yml
project:
  groups:
    - group: CMSE Library
      files:
        - file: $cmse-lib(Secure)$
```

The access sequence creates the project dependency. Confirm the resolved non-secure `*.cbuild.yml` points to the secure context's generated CMSE object.

## Common converter gaps

- Windows backslashes inside C/C++ `#include` directives fail on non-Windows hosts even when the XML file path was converted correctly.
- User commands may be ignored by `uv2csolution`; inspect before/after-build commands and recreate required steps with `solution.executes` only when they affect the build.
- An installed compiler may not be registered. Search vcpkg artifact locations for `armclang`, query its version, and export the corresponding `AC6_TOOLCHAIN_x_y_z` variable for validation.
- Regenerated pack configuration may use newer component versions. Inspect `.base@version` files and retain customized instances.
- When an RTE instance is missing, prefer the exact pack's configuration template. Recover ROM/RAM regions from `Cpu`, `OnChipMemories`, `TextAddressRange`, and `DataAddressRange`; recover security mode from `nSecure`. Treat heap, stack, veneer size, and partition settings not present in XML as explicit inferences.
- Do not copy memory settings from an example merely because it uses the same core. The device, TrustZone role, region bases, and sizes must agree with project metadata.
- A successful `csolution list contexts` proves structural resolution, not compilation or linking.

## Renesas RA Smart Configurator

Apply this procedure only when the input is a Renesas RA project generated by RA Smart Configurator (RASC). Confirm that from project evidence such as `configuration.xml`, `rasc_version.txt`, `via/rasc_*.via`, `script/fsp.scat`, or existing `rasc_launcher` commands; a Renesas vendor field alone is insufficient.

After the initial conversion, use the bundled [`RA_uVision_to_MDK6_v2.py`](../scripts/RA_uVision_to_MDK6_v2.py) helper to create the RASC pre- and post-build batch files and apply its related Cproject and scatter-file repairs. Before running it:

- Confirm that the project directory basename is also the generated `.cproject.yml` stem, because the helper derives the project name that way.
- Confirm that `script/fsp.scat`, the RASC via files, and the expected output target exist. The helper's post-build command assumes `Target_1`; verify this against the converted target and output metadata.
- Preserve existing `prebuild.bat` and `postbuild.bat` files separately. The helper backs up the Cproject and scatter file but replaces those batch files.
- Do not rerun the helper on an already repaired Cproject without checking for duplicate `generators` and `output` sections.

After running it, inspect every change rather than treating successful script completion as validation. Verify that:

- `prebuild.bat` invokes `rasc_launcher.bat` with `--generate`, `--compiler ARMv6`, `--devicefamily ra`, and the correct `configuration.xml`.
- `postbuild.bat` invokes `rasc_launcher.bat` with `--gensmartbundle` and the exact converted ELF/AXF output path.
- The converted Csolution executes the generated batch files at the correct before- and after-build stages. Recreate missing `solution.executes` entries when the converter omitted the original user commands.
- Via-file paths, `fsp.scat` sub-script paths, generator metadata, and ELF/HEX/MAP output settings remain valid and are not duplicated.

The generated batch files require the Windows RASC launcher. On another host, report that dependency if it prevents build validation; do not replace the commands with an unverified platform-specific equivalent.

## Useful inspections

```sh
rg -n '<(TargetName|Device|PackID|nSecure|ScatterFile|IncludePath|Define|Undefine|MiscControls|GroupName|FileName|FilePath|FileType)>' **/*.uvprojx
rg -n 'trustzone|cmse-lib|linker|output|file:' out/**/*.cbuild.yml
```

Adapt globbing to the shell and use `find` or `rg --files` when recursive `**` is unavailable.
